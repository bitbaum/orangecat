## Checks and limits

Regression tests cover current project-derived counts, approval copy/loading state, cached monetary suggestions, failed server writes, concurrent dismissal rollback, external-update disclosure and ordinary posts, and the three-event preview. Existing nudge-policy/language and repost tests also pass. Component fixtures were inspected at 390px and desktop using long labels and the screenshot's update pattern: no horizontal overflow, retained source links and original update text. The temporary fixture route was removed before committing.

The account's private dashboard was not accessed. Browser review used representative local fixtures; authenticated production behavior is additionally covered by the repository's CI browser gate. No account data was deleted or renamed.

## Remaining work

- Loki owns which descriptions it publishes through the external-publish contract. A reader-facing update should explain the change, rather than instruct readers to wait for a PR. Rendering preserves the original instead of inventing a summary.
- Test-looking project names are real rows from the owning actor's data, not a CSS defect. The fixture bootstrap can operate on an existing configured account; the screenshot alone cannot identify which credentials or writer created these rows. Confirm fixture-account isolation and cleanup policy before changing that data or the credential flow.
- Other application surfaces need the same spacing, target-size and data-state review before adopting scoped interface typography. The route inventory is in the earlier dated redesign audit. This review does not certify every page.
