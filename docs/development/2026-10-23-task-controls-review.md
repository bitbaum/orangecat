# Task controls review

A production Chromium phone flow opened Tasks and selected the recurring scheduled type. The emitted request was `?type=recurring_scheduled`; the API reads `task_type`. Show archived likewise sent `archived` while the API reads `is_archived`. The selects had no associated labels. Analytics and Filter hid their words on phones, and task cards navigated only through a div click.

The page now uses the API keys, named filters with shared field tokens, visible phone action labels and disclosure state. Task titles are native navigation links with a stretched card hit area, separate from named 44px status actions. Long titles and metadata wrap. Summary counts share one neutral surface instead of competing colored panels. Failed loading offers Retry. Empty filtered results offer Clear filters rather than a duplicate creation button. A request-version guard prevents an older response from overwriting a newer selection. Existing task visibility and write policies are unchanged; the review does not authorize modifying another person's task.

Three focused page tests passed: actual filter controls emit the expected query and reset, a failed request retries successfully, and an older response cannot replace the selected result. Source lint passed. A real Chromium 390px preview passed named filters, both API query keys, Clear filters resetting both choices, and no horizontal overflow. No task mutation was performed. Evidence: `/workspace/orangecat-review-evidence/task-controls-repaired-phone.png`. Full `pnpm run verify` passed (619 files, 5268 tests, 896.1 seconds). The commit hook applies formatting-only braces; file-size and lint checks are repeated afterward. Deployment verification remains pending.
